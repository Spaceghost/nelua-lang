# Truffle qualification and compilation experiment

The first built host in run 34774454020 failed because compilation diagnostics require explicit experimental-option permission. The next local probe exposed the language's unconditional package-path initialization attempting to obtain a real cwd under IOAccess.NONE. The fixed host enables only the diagnostic option class, retains host/class/process/thread denial, and supplies lexical virtual paths through a custom filesystem that denies every file read/write/attribute operation. It does not enable host filesystem access. Numeric arguments are passed as Java long, the representation supported by this language's numeric fast paths, rather than unadapted Java Integer.

Run 34774672271 completed the initial synchronous qualification and three-round HTTP comparison. Source probes observed missing coroutine support and character-count rather than Lua byte-count behavior for `#'é'`. Those failures remain explicit. These are not full async-worker or binary-string parity results.

The trace log also exposed a real optimization failure: partial evaluation recursively inlines `HashMap.TreeNode.find` from `LuaBlockNode`'s goto-label lookup and bails out with `Too deep inlining`. The `patch.py` candidate puts only those two cold label lookups behind a TruffleBoundary. It does not change the interpreter loop, remove an error check, or alter a benchmark result. Both original and patched language JARs are retained, and qualification output must match exactly before timing. Existing source-level UPL notices remain intact. The patch is an experiment on this specific community Lua implementation, not on GraalVM itself.

The repeated shootout includes JavaScript, unpatched Truffle, patched Truffle, and patched Truffle behind stock workerd's external service. All JVM contenders enable the documented JDK TCP_NODELAY option; a local transport probe exposed avoidable delayed-ACK cost otherwise. Both baseline and patch use identical host code, heap bounds, warmup and diagnostics. Four rounds rotate order. Compile traces remain evidence, not an assertion that every guest method reaches an optimized tier. No JIT speedup is accepted merely because the engine is named GraalVM.

The host remains trusted fixed-source and synchronous. It rejects unsupported async operations and non-ASCII byte strings instead of replacing them with blocking I/O or lossy text conversion. The framework's access flags plus our deny-only filesystem are not a proof that every builtin of this third-party language is safely sandboxed. There is no arbitrary-source HTTP endpoint.
